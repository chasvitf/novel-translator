# Novel Lock · แปลนิยายด้วย AI แบบชื่อไม่เพี้ยน

เว็บแอปแปลนิยายต่างประเทศเป็นภาษาไทยทีละหลายตอน ระบบจำชื่อตัวละคร สถานที่ และวิชาไว้ (อภิธานศัพท์) เพื่อให้ทุกตอนใช้ชื่อเดียวกัน
ทำให้ลูกค้าคนเดียวใช้ ไม่ได้ทำไว้ขาย หน้าเว็บจึงตั้งใจให้เรียบและใช้ง่าย

- **เว็บจริง:** https://novel-th.vercel.app
- **โค้ด:** https://github.com/chasvitf/novel-translator (deploy: `vercel deploy --prod --yes` จากโฟลเดอร์นี้ Vercel ไม่ deploy เองตอน push)
- **คู่มือใน Figma:** https://www.figma.com/design/kAf6vMGVrA70jYt52puCoI (ธีมมืด 8 สไลด์ **ยังเป็นแบบ 6 ขั้นเดิม** ส่วนเว็บตอนนี้เหลือ 5 ขั้น)

## หน้าที่ลูกค้าเห็น

| แท็บ | ทำอะไร |
|---|---|
| หน้าแรก | รายชื่อเรื่อง, คู่มือ 5 ขั้น, ปุ่มสร้างเรื่อง และปุ่มกู้คืนจากไฟล์สำรอง |
| ตอน | ลากไฟล์หรือวางข้อความ (แยกตอนให้เอง กี่พันตอนก็ได้), แปลทุกตอน / ตอนที่เลือก / ตอนเดียว |
| อ่าน | อ่านคำแปลเต็มหน้าในกรอบ ไม่มีไฮไลต์ มีปุ่มตอนก่อน/ตอนต่อไป อ่านระหว่างที่ตอนอื่นยังแปลอยู่ได้ |
| ตั้งค่าเรื่อง | ชื่อเรื่อง แนวเรื่อง ภาษา วิธีเขียนชื่อ ขัดเกลา คำสั่งเพิ่มเติมถึง AI (ขนาดท่อนอยู่ใน "ตั้งค่าขั้นสูง") |
| ส่งออก | Word .docx, E-book .epub, .txt, .zip แยกตอน, .txt ต้นฉบับคู่คำแปล, ไฟล์สำรอง .json |
| ตั้งค่า AI | ผู้ให้บริการ, key, โมเดล, **ความเร็ว**: แปลพร้อมกัน 1–8 ตอน และติ๊ก "key แบบเสียเงิน" (ไม่ต้องเว้นระยะรอโควตาฟรี และแก้ตอนที่ชื่อไม่ตรงให้เองหลังแปลจบ) |

หน้า **อ่าน & แก้** และ **อภิธานศัพท์** ซ่อนไว้ตามที่ลูกค้าต้องการ (โค้ดยังอยู่ใน `viewRead` / `viewGlossary` ระบบจำชื่อให้เองเบื้องหลัง)
ธีมมืดตลอด (`<html data-theme="dark">`) โลโก้เป็นหนังสือเปิด + แม่กุญแจ (`public/favicon.svg`)
ปุ่มย้อนกลับของเบราว์เซอร์ใช้ได้ (แต่ละหน้ามี `#view` ใน URL)

## AI ที่รองรับ

Gemini (ฟรี ต้องมี key ได้ราว 20 ครั้ง/วัน/โมเดล หมดแล้วสลับโมเดลให้เอง โมเดลที่ล่ม (503) จะถูกข้ามไป 3 นาที), Pollinations (ไม่ต้องมี key แต่ช้าและด้อยกว่า), Groq, OpenRouter, OpenAI, Anthropic Claude, OpenAI-compatible / Ollama
key เก็บใน `localStorage` และส่งตรงไปที่ผู้ให้บริการ นิยายและคำแปลเก็บใน IndexedDB ของเครื่อง ไม่มีเซิร์ฟเวอร์ของเรา

## โครงสร้าง

เว็บ static ไม่ต้อง build

```
public/index.html, css/app.css, js/app.js   หน้าเว็บทั้งหมด (view*, actions, runQueue = แปลหลายตอนแบบมี worker)
public/js/lib/split.js       แยกตอน (第N章/回, 제N화, Chapter N, ตอนที่ N, ===) แบ่งท่อน
public/js/lib/glossary.js    อภิธานศัพท์ ตรวจคำแปล (ชื่อไม่ตรง / อักษรต่างภาษาหลุด)
public/js/lib/prompts.js     prompt แปล / ขัดเกลา / แก้ / หาคำใหม่
public/js/lib/pipeline.js    ขั้นตอนแปลหนึ่งตอน
public/js/lib/providers.js   เรียก AI, เว้นระยะ, retry, สลับโมเดล, พักโมเดลที่ล่ม
public/js/lib/files.js       นำเข้า/ส่งออกไฟล์
scripts/run_corpus.mjs       แปลชุดทดสอบนิยายจริงด้วย API จริง (key จาก .env)
scripts/run_parallel.mjs     แปลทั้งเล่มจริงแบบพร้อมกันหลายตอน (เหมือนโหมด key เสียเงิน)
tests/                       node --test (19 ข้อ)
```

```bash
npm test                                   # unit tests
npm run dev                                # http://localhost:8765
node scripts/run_parallel.mjs 3            # 西遊記 5 ตอนจริง แปลพร้อมกัน 3 ตอน → corpus/out/parallel/
```

## สถานะการทดสอบ (2026-10-22)

**ผ่านแล้ว**
- ทดสอบทั้งระบบด้วยเบราว์เซอร์อัตโนมัติ (agent-browser) กับ AI จำลอง: นำเข้า 1,000 ตอน, แปลตอนเดียว/ทุกตอน/พร้อมกัน, อ่านระหว่างแปล, หยุด, ปุ่มย้อนกลับ, ส่งออกทุกแบบ, สำรองแล้วกู้คืน, สร้าง/เปลี่ยนชื่อ/ลบเรื่อง, จอมือถือ 390px ไม่ล้น, ไม่มี error ใน console
- แปลจริงด้วย Gemini: 羅生門 ทั้งเรื่อง ชื่อไม่ตรง 0, อักษรหลุด 0
- แปลจริงพร้อมกัน 3 ตอน (西遊記 5 ตอน): ครบ 5/5 ใน 195 วินาที, 38 ครั้ง, ไม่โดนจำกัดความถี่, ระบบจำชื่อได้ 86 คำ
- โควต้าของโมเดลแรกหมดกลางทาง: สลับโมเดลให้เองแล้วแปลต่อจนครบ 6/6
- .docx เปิดได้ด้วยตัวอ่านเอกสารของ macOS (`textutil`) ภาษาไทยถูกต้อง

**ต้องทำต่อพรุ่งนี้**
1. ~~**ชื่อไม่ตรงหลังแปลพร้อมกัน**~~ เสร็จ 22 ต.ค.: สคริปต์มีขั้นแก้แล้ว ชื่อไม่ตรงเหลือ 0 ทุกตอน อักษรหลุด 1 จุด (อักษรอาร์เมเนีย "ակ" ใน "มหակัปป์") แก้ด้วย `patchLeftovers` ที่ส่งไปแก้เฉพาะคำรอบๆ แทนทั้งช่วง ทดสอบกับ Gemini จริงแล้วเหลือ 0
2. **โควต้าหมดทุกโมเดล (scenario B ใน `part7b.sh`):** หยุดก่อนจะได้ผล รอบแรกที่ผลปนกันเห็นว่าระบบหยุดและขึ้นข้อความว่า "โควตาฟรีของวันนี้หมดทุกโมเดลแล้ว…" ส่วนตอนที่เหลือยังเป็น "ยังไม่แปล" ให้รันซ้ำแบบแยก scenario
3. **iPhone Safari:** เครื่องนี้ไม่มี Xcode ให้ทดสอบด้วย WebKit (`npx playwright install webkit`) กับ device iPhone หรือเปิดบน iPhone จริง
4. ~~**.epub**~~ เสร็จ 22 ต.ค.: epubcheck 5.1.0 ผ่าน 0 errors/0 warnings (5 ตอนจริง + ชื่อที่มี <&>")
   เดิม: ดาวน์โหลด epubcheck 5.1.0 และติดตั้ง OpenJDK (brew) แล้ว แต่ยังไม่ได้รัน
   `$(brew --prefix openjdk)/bin/java -jar epubcheck-5.1.0/epubcheck.jar ไฟล์.epub`
5. ~~**.docx ใน Pages**~~ เสร็จ 22 ต.ค.: เจอบั๊ก Pages แสดงเนื้อหาทั้งหมดเป็นตัวหนาจัดกลางเหมือนหัวข้อ (ไม่มีสไตล์ Normal) แก้แล้ว เปิดใน Pages ได้ 166 หน้าถูกต้อง ยังไม่ได้ลองใน Word
   เดิม: ส่งออกจากคำแปลจริงแล้วเปิดในโปรแกรมจริง
6. **key แบบเสียเงินจริง:** ยังไม่มี key ให้ทดสอบ

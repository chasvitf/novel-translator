# Novel Lock · แปลนิยายด้วย AI แบบชื่อไม่เพี้ยน

เว็บแอปแปลนิยายต่างประเทศเป็นภาษาไทยทีละหลายตอน ระบบจำชื่อตัวละคร สถานที่ และวิชาไว้ (อภิธานศัพท์) เพื่อให้ทุกตอนใช้ชื่อเดียวกัน
ทำให้ลูกค้าคนเดียวใช้ ไม่ได้ทำไว้ขาย หน้าเว็บจึงตั้งใจให้เรียบและใช้ง่าย

- **เว็บจริง:** https://novel-th.vercel.app
- **โค้ด:** https://github.com/chasvitf/novel-translator (deploy: `vercel deploy --prod --yes` จากโฟลเดอร์นี้ Vercel ไม่ deploy เองตอน push)
- **คู่มือใน Figma:** https://www.figma.com/design/kAf6vMGVrA70jYt52puCoI (ธีมมืด 8 สไลด์ **ยังเป็นแบบ 6 ขั้นเดิม** ส่วนเว็บตอนนี้เหลือ 5 ขั้น)

## หน้าที่ลูกค้าเห็น

| แท็บ | ทำอะไร |
|---|---|
| หน้าแรก | รายชื่อเรื่อง, คู่มือ 5 ขั้น, ปุ่มสร้างเรื่อง และปุ่มกู้คืนจากไฟล์สำรอง |
| ตอน | ลากไฟล์หรือวางข้อความ (แยกตอนให้เอง กี่พันตอนก็ได้), แปลทุกตอน / ตอนที่เลือก / ตอนเดียว |
| อ่าน | อ่านคำแปลเต็มหน้าในกรอบ ไม่มีไฮไลต์ มีปุ่มตอนก่อน/ตอนต่อไป อ่านระหว่างที่ตอนอื่นยังแปลอยู่ได้ |
| ตั้งค่าเรื่อง | ชื่อเรื่อง แนวเรื่อง ภาษา วิธีเขียนชื่อ ขัดเกลา คำสั่งเพิ่มเติมถึง AI (ขนาดท่อนอยู่ใน "ตั้งค่าขั้นสูง") |
| ส่งออก | Word .docx, E-book .epub, .txt, .zip แยกตอน, .txt ต้นฉบับคู่คำแปล, ไฟล์สำรอง .json |
| ตั้งค่า AI | ผู้ให้บริการ, key, โมเดล, **ความเร็ว**: แปลพร้อมกัน 1–8 ตอน และติ๊ก "key แบบเสียเงิน" (ไม่ต้องเว้นระยะรอโควตาฟรี และแก้ตอนที่ชื่อไม่ตรงให้เองหลังแปลจบ) |

หน้า **อ่าน & แก้** และ **อภิธานศัพท์** ซ่อนไว้ตามที่ลูกค้าต้องการ (โค้ดยังอยู่ใน `viewRead` / `viewGlossary` ระบบจำชื่อให้เองเบื้องหลัง)
ธีมมืดตลอด (`<html data-theme="dark">`) โลโก้เป็นหนังสือเปิด + แม่กุญแจ (`public/favicon.svg`)
ปุ่มย้อนกลับของเบราว์เซอร์ใช้ได้ (แต่ละหน้ามี `#view` ใน URL)

## AI ที่รองรับ

Gemini (ฟรี ต้องมี key ได้ราว 20 ครั้ง/วัน/โมเดล หมดแล้วสลับโมเดลให้เอง โมเดลที่ล่ม (503) จะถูกข้ามไป 3 นาที), Groq, OpenRouter, OpenAI, Anthropic Claude, OpenAI-compatible / Ollama
key เก็บใน `localStorage` และส่งตรงไปที่ผู้ให้บริการ นิยายและคำแปลเก็บใน IndexedDB ของเครื่อง ไม่มีเซิร์ฟเวอร์ของเรา

## โครงสร้าง

เว็บ static ไม่ต้อง build

```
public/index.html, css/app.css, js/app.js   หน้าเว็บทั้งหมด (view*, actions, runQueue เรียก runChapters แล้วบันทึกทีละตอน)
public/js/lib/split.js       แยกตอน (第N章/回, 제N화, Chapter N, ตอนที่ N, ===) แบ่งท่อน
public/js/lib/glossary.js    อภิธานศัพท์ ตรวจคำแปล (ชื่อไม่ตรง / อักษรต่างภาษาหลุด / ย่อหน้าหาย สั้นผิดปกติ บทพูดเสีย)
public/js/lib/prompts.js     prompt แปล / ขัดเกลา / แก้ / หาคำใหม่ / ตรวจเทียบต้นฉบับ / แก้ทีละย่อหน้า
public/js/lib/pipeline.js    ขั้นตอนแปลหนึ่งตอน, ซ่อมย่อหน้า, ตรวจโดย AI อีกตัว, runChapters (คิวงานหลายตอน), resetStuck
public/js/lib/providers.js   เรียก AI, เว้นระยะ, timeout 180 วิ, retry แบบ backoff+jitter, สลับโมเดล, พักโมเดลที่ล่ม
public/js/lib/files.js       นำเข้า/ส่งออกไฟล์
scripts/run_corpus.mjs       แปลชุดทดสอบนิยายจริงด้วย API จริง (key จาก .env)
scripts/run_parallel.mjs     แปลทั้งเล่มจริงแบบพร้อมกันหลายตอน (เหมือนโหมด key เสียเงิน)
public/js/lib/store.js       IndexedDB (ทั้งเรื่องเป็น 1 record มี rev กันแท็บอื่นเขียนทับ) + localStorage
tests/                       node --test: core.test.mjs + jobs.test.mjs (45 ข้อ, AI จำลองทั้งหมด) · tests/e2e/ เบราว์เซอร์ + mock.mjs
```

```bash
npm test                                   # unit tests
npm run dev                                # http://localhost:8765
node scripts/run_parallel.mjs 3            # 西遊記 5 ตอนจริง แปลพร้อมกัน 3 ตอน → corpus/out/parallel/
REVIEW=1 node scripts/run_parallel.mjs 2 zh-xiyouji-01.txt zh-xiyouji-02.txt   # 2 ตอนจริง + ให้ AI อีกตัวตรวจ
```

## งานใหญ่ (เช่น 1,000 ตอน)

**ทำไมเดิมแปลได้ราว 10 ตอนแล้วหยุด:** ไม่ใช่ขีดจำกัดในโค้ด (ไม่มีจุดไหนจำกัดจำนวนตอน) แต่เป็นโควตาฟรีของ Gemini
วัดจริงในโปรเจกต์นี้ได้ราว 20 ครั้ง/วัน/โมเดล (Google ไม่ได้ประกาศตัวเลขต่อโมเดล ดูได้ที่ AI Studio → Rate limit; โควตานับ**ต่อโปรเจกต์ Google ไม่ใช่ต่อ key** และรีเซ็ตเที่ยงคืนเวลาแปซิฟิก)
ส่วนหนึ่งตอนใช้ราว 10 ครั้ง (วัดจริง 48 ครั้ง/5 ตอน: หาคำใหม่ 1 + แปลทีละท่อน + แก้ชื่ออัตโนมัติ) เมื่อทุกโมเดลในรายการหมดโควตา ระบบหยุดเอง (ถูกต้อง ไม่ได้ค้าง)

**ระบบงานตอนนี้** (`runChapters` ใน `pipeline.js`)
- สถานะต่อตอน: ยังไม่แปล → กำลังแปล → แปลเสร็จแล้ว / ผิดพลาด
- บันทึกลงเครื่องทันทีเมื่อเสร็จแต่ละตอน ปิดแท็บหรือเครื่องดับเสียแค่ตอนที่กำลังแปลอยู่ เปิดใหม่แล้วกด “แปลที่ยังไม่แปล” แปลต่อเฉพาะที่เหลือ ไม่แปลซ้ำ
- ตอนเดียวผิดพลาดไม่หยุดตอนอื่น · โควตาหมดทุกโมเดล / key ผิด / กดหยุด / AI ไม่ตอบติดกัน 3 ตอน → หยุดทั้งงาน เก็บตอนที่เสร็จไว้
- คำตอบที่สั้นกว่า 20% ของต้นฉบับ (เช่นคำปฏิเสธ “ขออภัย…”) ไม่ถูกบันทึกเป็นคำแปล: ผ่าครึ่งแล้วลองใหม่ ถ้ายังไม่ได้ขึ้น “ผิดพลาด”
- Android ปิดแท็บที่อยู่เบื้องหลังนานๆ: เปิดเรื่องอีกครั้งแล้วระบบแปลต่อจากที่ค้างเอง (รายการตอนที่เหลือเก็บใน localStorage `nl:run:<id>`) กดหยุดเองหรือโควตาหมดจะไม่แปลต่อเอง
- ระหว่างแปล ขอให้หน้าจอไม่ดับ (Screen Wake Lock, Chrome บน Android รองรับ) เพราะ Android หยุดแท็บเมื่อปิดจอ · สลับไปแอปอื่นยังหยุดอยู่ กลับมากด “แปลที่ยังไม่แปล” ได้
- ทุกคำขอมี timeout 180 วินาที · ถูกจำกัดความถี่ / เซิร์ฟเวอร์ขัดข้อง → รอแบบ backoff + jitter ไม่เกิน 6 ครั้ง · คำขอผิดรูปแบบ (400) ไม่ลองซ้ำ · 503 สลับโมเดล
- เปิดเรื่องเดียวกันสองแท็บ: แท็บที่ข้อมูลเก่ากว่าบันทึกไม่ได้ (ขึ้นข้อความให้ปิดแท็บอื่น) แทนที่จะเขียนทับตอนที่อีกแท็บแปลไว้
- แต่ละตอนเก็บ `stats` (จำนวนครั้งที่เรียก AI สำเร็จ, token, เวลา) ท้ายงานแสดงรวม

**Gemini ฟรีวันละกี่ตอน (วัดจริง 2026-10-25)**: ตั้งค่าประหยัดโควตา (ปิดแก้ชื่ออัตโนมัติ, ขนาดท่อน 8000, เปิดจำชื่อใหม่) ใช้ 2 ครั้ง/ตอน ตอนละราว 45 วินาที
โมเดลตระกูล flash 3 ตัวได้ 20 ครั้ง/วันต่อตัว (จาก error ของ Google เอง) ≈ 30 ตอน · gemini-3.5-flash-lite ได้มากกว่า 105 ครั้ง/วัน (ยังไม่หมดตอนหยุดวัด) ≈ 50+ ตอน → **อย่างน้อยราว 80 ตอน/วัน** · โมเดลอื่นยังไม่ได้วัด
Pollinations ถอดออกแล้ว (2026-10-25): วัดจริงราว 17 นาที/ตอน มีภาษาจีนหลุดในคำแปล และคำแก้ถูกด่านกันรับไม่ได้เกือบทั้งหมด ผู้ใช้ที่เคยเลือกไว้จะถูกเปลี่ยนเป็น Gemini เอง

**วิธีแปล 1,000 ตอน**
1. ใช้ key แบบเสียเงิน (Tier 1 ขึ้นไป) ถ้าต้องการเสร็จในไม่กี่วัน: ด้วยโควตาฟรีราว 20 ครั้ง/วัน/โมเดล 1,000 ตอน × 3–10 ครั้ง = 3,000–10,000 ครั้ง ใช้เวลาหลายสัปดาห์
2. ตั้งค่า AI → ติ๊ก “key แบบเสียเงิน” และแปลพร้อมกัน 4–8 ตอน (ทดสอบกับ AI จำลองที่ 8 ตอนพร้อมกันแล้ว)
3. แปลก่อน 10–20 ตอน อ่านตรวจ แล้วดู `ใช้ AI … ครั้ง · … token` ท้ายงานเพื่อคำนวณค่าใช้จ่ายจริง (token × ราคาโมเดลในหน้าราคาของผู้ให้บริการ)
4. กด “แปลที่ยังไม่แปล” ถ้าหยุดกลางทาง (โควตา/ปิดเครื่อง) กดอีกครั้งเมื่อพร้อม
5. ส่งออกไฟล์สำรอง .json เป็นระยะ (ข้อมูลอยู่ในเบราว์เซอร์เครื่องเดียว)

**ข้อจำกัดที่รู้**: ทั้งเรื่องเก็บเป็น record เดียวใน IndexedDB ทุกครั้งที่บันทึกเขียนใหม่ทั้งก้อน วัดที่ 1,000 ตอน (35.8 ล้านตัวอักษร) งานหยุดชะงักหน้าจอนานสุด 153 ms ยังใช้ได้ ถ้าใหญ่กว่านี้มากควรแยกเก็บทีละตอน · ต้องเปิดแท็บไว้ระหว่างแปล · ไม่รอโควตารีเซ็ตแล้วแปลต่อเอง

## ตรวจคุณภาพ

ไม่มีการตรวจอัตโนมัติไหนพิสูจน์ได้ว่าคำแปลถูกต้อง ระบบแค่ชี้จุดที่น่าสงสัยให้คนไปดู

1. **ตรวจด้วยโปรแกรม (ทุกตอน ไม่เสียโควตา)**: ชื่อไม่ตรงอภิธานศัพท์, อักษรต่างภาษาหลุด, คำแปลมีย่อหน้าน้อยกว่าต้นฉบับ (อาจหาย), ย่อหน้าที่สั้นผิดปกติเทียบกับสัดส่วนของท่อนนั้นเอง (อาจตกหล่น), บทพูดที่เครื่องหมายคำพูดหาย
   ไม่ flag กรณีคำแปลมีย่อหน้า*มากกว่า* (วัดจากคำแปล Gemini จริง: บทกลอนถูกแยกบรรทัดบ่อย 35 → 81 ย่อหน้า ไม่ได้หายอะไร)
2. **ซ่อมเฉพาะจุด (ถ้าเปิด “ตรวจและแก้ชื่อที่เพี้ยนอัตโนมัติ”)**: ย่อหน้าหาย → แปลท่อนนั้นใหม่ 1 ครั้ง, ย่อหน้าสั้น/บทพูดเสีย → แปลเฉพาะย่อหน้านั้นใหม่ เก็บผลใหม่เมื่อปัญหาลดลงเท่านั้น การแก้ชื่อที่ทำให้ย่อหน้าหายจะถูกปฏิเสธ
3. **ให้ AI อีกตัวตรวจเทียบต้นฉบับ (ตั้งค่าเรื่อง ปิดไว้ก่อน)**: ใช้โมเดลถัดไปในรายการ (ไม่ใช่ตัวที่แปล) หาความหมายผิด ตกหล่น เติมเอง ชื่อ/สรรพนาม/ความสัมพันธ์ผิด สลับคนพูด ขัดกับเรื่องก่อนหน้า ต้องยกข้อความจากต้นฉบับและคำแปลมา ถ้ายกข้อความที่ไม่มีอยู่จริง ทิ้งข้อนั้น
   แก้ทีละย่อหน้าไม่เกิน `maxCorrections` (3) ย่อหน้าต่อท่อน แล้วให้ตรวจซ้ำรวมครั้งเดียว ที่เหลือเก็บเป็น “ควรเช็ก” ให้คน · เพิ่มการเรียก AI ได้ถึง 5 ครั้งต่อท่อน
4. **รายงาน**: ท้ายตอนในหน้าอ่านมีรายการจุดที่พบ และบอกชัดว่า “ยังไม่ใช่การตรวจโดยคน” · `chapter.issues`, `chapter.review` (found / fixed / unresolved / model / error), `chapter.stats`
